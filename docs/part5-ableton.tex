\chapter{La refonte multi-projecteurs}
\label{ch:multi}

Le contrôleur d'origine ne pilotait qu'un seul projecteur. Pour produire de
vrais jeux de lumière, \Icare{} gère désormais un \textbf{patch} complet : une
liste de projecteurs, chacun décrit par un \emph{profil} (plan de canaux) et une
\emph{adresse} de départ dans l'univers DMX.

\section{Les profils de projecteurs}

Un profil dit quel canal fait quoi. \Icare{} embarqué les profils suivants,
qui correspondent au matériel :

  \centering
  \begin{tabular}{@{}llcp{5.4cm}@{}}
    \toprule
    \textbf{Profil} & \textbf{Canaux} & \textbf{Faisceau} & \textbf{Détail} \\
    \midrule
    \code{rgbwa\_par\_5ch} & 5 & $30\textdegree$ & Rouge, Vert, Bleu, Blanc, Ambre. \\
    \addlinespace
    \code{wild\_wash\_132\_6ch} & 6 & $75\textdegree$ & Intensité, Strobe, Rouge,
      Vert, Bleu, sensibilité son. \\
    \addlinespace
    \code{cameo\_qspot40\_9ch} & 9 & $15\textdegree$ & Intensité, intensité fine,

Le patch est validé au chargement : un profil inconnu, un chevauchement de
canaux ou une adresse hors de l'univers sont refusés. Il vit dans
\file{patch.json} à côté de l'exécutable et peut être modifié depuis l'API
\api{POST /api/patch}.

\section{Comment le rendu gère les différences}

Chaque mode \og{}génératif\fg{} (couleur fixe, effets, aléatoire, audio)
produit une couleur et une intensité globales. Le moteur l'écrit sur chaque
projecteur :

\begin{itemize}[leftmargin=1.4em]
  \item si le profil possède un \textbf{canal d'intensité}, il est écrit tel
        quel et les couleurs en brut ;
  \item sinon (PAR RGBWA 5 canaux), les couleurs sont \textbf{multipliées par
        l'intensité} : c'est l'intensité qui pilote la luminosité.
\end{itemize}

Le brouillard possède ses propres canaux, indépendants des modes : on peut
l'activer séparément via \api{POST /api/fog}.

\begin{note}
Le Q-Spot 40 et le Wild Wash sont des projecteurs \textbf{fixes} : leurs profils
n'ont ni pan ni tilt. Les curseurs de position de l'onglet Direct ne servent
donc qu'à la visualisation 3D.
\end{note}

\chapter{Les « looks »}
\label{ch:looks}

Un \textbf{look} est un état de lumière statique que l'on peut rappeler : une
liste de cibles et, pour chacune, une couleur et une intensité.

\section{Cibles}

Une cible peut être :

\begin{itemize}[leftmargin=1.4em]
  \item \code{"*"} : tous les projecteurs ;
  \item le nom d'un \textbf{groupe} (\code{pars}, \code{wash}, \code{spots},
        \code{fx}) ;
  \item le nom d'un \textbf{projecteur} précis (\code{QSpot1}, \code{Fog}\dots).
\end{itemize}

Les cibles sont fusionnées dans l'ordre \code{"*"}, puis le groupe, puis le
nom : on met donc une base globale et on surcharge au besoin.

\section{Résolution}

\code{resolve()} transforme le look en valeurs de canaux concrètes. Pour un
projecteur sans canal d'intensité, l'intensité demandée \og{}multiplie\fg{} les
couleurs. Exemple de look :

\begin{lstlisting}[language=json,caption={Un look : base bleue, projecteurs rouges.}]
{
  "name": "Refrain",
  "targets": {
    "pars":  { "r": 0, "g": 0, "b": 255, "dimmer": 220 },
    "QSpot1": { "r": 255, "g": 80, "b": 0 }
  },
  "fog": { "level": 120 }
}
\end{lstlisting}

Les looks sont de simples fichiers JSON dans \file{Looks/}, créés depuis
l'onglet \textbf{Show} : on choisit un nom, une cible, une couleur et une
intensité, puis on sauvegarde.

\section{Installation}

\begin{enumerate}[leftmargin=1.6em]
  \item Exécuter \file{tools\textbackslash install\_abletonosc.ps1} : le script
        télécharge AbletonOSC et le copie dans
        \file{Documents\textbackslash Ableton\textbackslash User Library\textbackslash Remote Scripts}.
  \item Redémarrer Live.
  \item \emph{Préférences $\rightarrow$ Link, Tempo \& MIDI} $\rightarrow$
        Control Surface = \textbf{AbletonOSC}.
  \item Dans \Icare{}, onglet \textbf{Show} $\rightarrow$ \textbf{Connecter
        Ableton}. Le témoin passe au vert.
\end{enumerate}

\begin{note}
Sans Ableton, le lien reste simplement \og{}déconnecté\fg{} : \Icare{} continue
de fonctionner normalement.
\end{note}

\section{Mapper les scènes aux looks}

L'onglet \textbf{Show} liste les scènes d'Ableton (récupérées via OSC). Pour
chacune, on choisit le look à déclencher. Dès qu'une scène est sélectionnée ou
lancée dans Ableton, \Icare{} applique le look correspondant.

\begin{lstlisting}[caption={Mapping persistant (scenes.json).},numbers=none]
{ "enabled": true,
  "mapping": { "INTRO": "intro_bleu", "A": "couplet", "CHORUS": "refrain" } }
\end{lstlisting}

\section{Produire son show}

Une méthode simple, adaptée au template Ableton du studio :

\begin{enumerate}[leftmargin=1.6em]
  \item Dans \Icare{}, créer un look par ambiance : \code{INTRO},
        \code{A}, \code{B}, \code{CHORUS}, \code{BREAK}, \code{SOLO},
        \code{OUTRO}.
  \item Mapper chaque scène Ableton au look du même nom, une fois pour toutes.
  \item En répétition ou en concert, il suffit de lancer les scènes dans
        Ableton : les lumières suivent.
  \item Réglage fin : le \emph{beat} d'Ableton pourra servir plus tard à caler
        les effets (strobe sur le temps, chenillard à la mesure).
\end{enumerate}

\chapter{La simulation 3D}
\label{ch:simulation}

L'onglet \textbf{Show} dessine toute la scène, sans aucun matériel, à partir de
l'état DMX réel (\api{GET /api/simulation}). On peut ainsi concevoir les looks
et vérifier le rendu avant la répétition.

\begin{itemize}[leftmargin=1.4em]
  \item chaque projecteur est placé à sa position \code{(x, z)} et orienté par
        son \code{angle} ;
  \item son \textbf{faisceau} a le rayon réel de son profil :
        $r = d \times \tan(\text{angle}/2)$ --- un PAR ($30\textdegree$) est
        étroit, un Wild Wash ($75\textdegree$) très large, un Q-Spot
        ($15\textdegree$) serré ;
  \item la couleur et l'intensité du faisceau suivent les canaux DMX.
\end{itemize}

\paragraph{Un rendu optique, pas un dessin.} Les faisceaux ne sont pas des cônes
pleins : ils sont calculés par un shader qui reproduit les propriétés d'un
faisceau réel.

\begin{itemize}[leftmargin=1.4em]
  \item \textbf{Forme} : les projecteurs à LED ponctuelle (PAR, Q-Spot) émettent
        un \textbf{cône} ; le \textbf{Wild Wash}, qui est une \emph{barre} de
        LEDs, émet un \textbf{ventilateur plat} (section elliptique) --- tout
        comme un vrai wash linéaire.
  \item \textbf{Contours} : seul le \textbf{Cameo Q-Spot 40}, à l'optique
        serrée, a un contour \emph{net} ; le PAR et surtout le Wild Wash ont des
        bords très \emph{doux}.
  \item \textbf{Décroissance radiale} : le faisceau est plus intense sur son axe
        et s'éteint vers ses bords.
  \item \textbf{Décroissance axiale} : l'intensité diminue avec la distance.
  \item \textbf{Pièce au sol} : à l'intersection du faisceau et du sol, une
        \emph{flaque} de lumière elliptique apparaît, dimensionnée par l'angle.
  \item \textbf{Tone mapping ACES} et sortie sRGB : les recouvrements de
        faisceaux «{}brûlent{}» vers le blanc au lieu de saturer brutalement,
        comme sur une image filmée.
  \item La salle est \textbf{sombre} ; seul ce que la lumière touche est visible.
        Un curseur \emph{Exposition} règle l'ensemble.
\end{itemize}

Le \textbf{corps} de chaque projecteur reprend sa forme réelle : une longue
\textbf{barre} avec sa ligne de LEDs pour le Wild Wash, un disque ou une
lentille pour le PAR et le Q-Spot.

\paragraph{La fumée est éclairée par les lumières.} La fumée n'est pas
auto-éclairée : chaque particule reçoit la lumière \emph{qui l'atteint
réellement}. On teste, pour chaque faisceau allumé, si la particule tombe dans
son cône, puis on accumule contribution radiale et axiale. La couleur et
l'opacité de la particule en découlent :

\begin{equation*}
\text{éclairement} = \sum_{\text{feux}} I_f \cdot
\left(1 - \frac{r}{r_{\max}}\right)^{2} \cdot
\left(0{,}35 + 0{,}65\,\Big(1 - \frac{d}{L}\Big)\right).
\end{equation*}

Hors de tout faisceau, il ne reste qu'un \textbf{très léger} voile naturel
($\approx 3{,}5\,\%$), conformément au rendu réel : sans lumière qui la frappe,
la fumée est sombre.

\chapter{Le morceau test (sans Ableton)}
\label{ch:testshow}

Pour vérifier toute la chaîne sans Ableton, \Icare{} sait jouer un
\textbf{morceau test} : une \emph{timeline} de cues décrite dans un fichier
JSON (\file{Shows/}). Le lecteur tourne dans un thread et pilote le même
contrôleur DMX; l'interface et la simulation 3D suivent automatiquement.

\section{Format d'un cue}

\begin{table}[H]
  \centering
  \begin{tabular}{@{}lp{8.6cm}@{}}
    \toprule
    \textbf{Type} & \textbf{Effet} \\
    \midrule
    \code{look} & Rappelle un look par son nom. \\
    \code{effect} & Lance un effet (rainbow, fire, police, chase). \\
    \code{strobe} & Strobe plein cadre (\code{freq}, \code{shuffle}). \\
    \code{fog} & Fixe le niveau de fumée. \\
    \code{blackout} & Éteint tout. \\
    \bottomrule
  \end{tabular}
  \caption{Types de cues.}
\end{table}

Chaque cue dure \code{seconds} secondes, ou \code{beats} temps au tempo du
morceau (\code{bpm}). Un champ \code{fog} optionnel fixe la fumée pour la
durée du cue --- et \emph{prime} sur la fumée du look.

\begin{lstlisting}[language=json,caption={Extrait de \file{Shows/demo.json}.}]
{
  "name": "Morceau test",
  "bpm": 120,
  "cues": [
    { "type": "look",  "name": "INTRO", "seconds": 8, "fog": 20 },
    { "type": "look",  "name": "A",     "seconds": 8, "fog": 60 },
    { "type": "look",  "name": "CHORUS","seconds": 10, "fog": 180 },
    { "type": "strobe","freq": 10,      "seconds": 3,  "fog": 160 },
    { "type": "effect","name": "rainbow","seconds": 8, "fog": 140 },
    { "type": "blackout","seconds": 4 }
  ]
}
\end{lstlisting}

\section{Mise en oeuvre}

Dans l'onglet \textbf{Show}, le panneau \emph{Morceau test} propose la liste des
morceaux, les boutons \emph{Lancer}, \emph{Pause} et \emph{Stop}, et une barre
de progression indiquant le cue courant. Côté API :
\api{GET /api/show/list}, \api{GET /api/show/status},
\api{POST /api/show/play}, \api{POST /api/show/pause},
\api{POST /api/show/stop}.

Le morceau \file{Shows/demo.json} fourni parcourt 13 cues : entrée en bleu,
montée en énergie, refrain, strobe, break, arc-en-ciel, gyrophare, solo,
chenillard, feu, sortie et noir. C'est le moyen le plus simple de tester les
looks, les effets, la fumée et la 3D d'un seul geste.

Le moteur DMX garde la même surface publique qu'avant (\code{set\_values},
\code{strobe}, \code{effect\_*,} \code{audio\_push}, \code{health}, \dots), mais
les applique désormais au \textbf{patch entier}. Les anciennes fonctions de
l'onglet Direct et le lecteur de séquences continuent donc de fonctionner.

\begin{note}
Le contrôleur par défaut écrivait une seule adresse de couleur. Il écrit
maintenant une \emph{frame} complète : pour chaque projecteur, les canaux de son
profil sont remplis, ce qui rend possible un rendu différent d'un appareil à
l'autre.
\end{note}
